# 會考複習總覽（P1–P3：單機＋雲端同步＋老師端）

給國中學生準備會考用的小 App：

- **章節**：每一節自己評熟悉度 1–5 分，記錄複習了幾次。
- **總覽**：會考倒數、紅黃綠色塊一眼看出哪裡弱、「優先衝刺清單」（分數低、複習少的排前面）。複習 3 次以上還是 1–2 分，會標「需要老師幫忙」。
- **計畫**：把章節卡排進每週、每天的格子。手機：按「＋加入章節」→ 點章節 → 點日期。電腦：從左邊章節池拖到日期格（點一下再點日期也可以）。
- **今天**：今天要複習的卡片，按「完成」次數自動 +1，順便問現在幾分；沒做完的舊卡會以「逾期」排在最上面。

- **雲端同步（P3）**：學生用老師給的專屬連結打開，進度自動存到雲端；手機、電腦都能用，離線改的等有網路再補傳。畫面上方會顯示「已同步／同步中…／離線，稍後上傳」。沒有連結時，資料只存在這台裝置（跟以前一樣）。
- **老師端（P3）**：網址加 `?teacher=1`，看每位學生的紅色節數、逾期卡數，點進去用同一套畫面「只看不改」。

## 檔案

| 檔案 | 用途 |
|---|---|
| `index.html` | 整個 App（單檔，不用安裝任何東西） |
| `data/math-kx-108.json` | 數學章節表（康軒，58 節，來源：均一教育平台 類康軒版，依康軒 113 學年度章節架構） |
| `embed_catalog.py` | 把章節表複製一份進 `index.html`（直接雙擊開檔時用） |
| `sw.js`、`manifest.json`、`icon-*.png` | 讓手機可以「加到主畫面」、離線也開得起來 |
| `vendor/supabase.js` | 連雲端用的工具包（從統測單字 App 複製的同一份） |
| `supabase/001_hk.sql` | 雲端資料表與權限（貼到 Supabase 執行一次） |
| `supabase/002_verify_hk.sql` | 權限檢查（001 之後執行，確認門鎖有鎖好） |
| `supabase/003_hk_backup.sql` | 每日備份（每位學生每天第一次上傳前，先把雲端那份存起來） |
| `supabase/004_verify_backup.sql` | 備份檢查（003 之後執行） |
| `supabase/SECURITY.md` | 安全設計說明：誰看得到什麼、連結外流怎麼辦 |

## 本機測試

```bash
cd ~/projects/felix_agent/tutoring/會考複習總覽
python3 -m http.server 8791
```

瀏覽器開 `http://127.0.0.1:8791/`。自我測試：`http://127.0.0.1:8791/?selftest=1`（全部顯示「通過」才算 OK；自我測試用的是另一份暫存資料，不會洗掉你的紀錄，也不會連雲端）。

老師端示範（假資料、不連雲端，可以隨便按）：`http://127.0.0.1:8791/?selftest=teacher`。

直接雙擊 `index.html`（file:// 開）也能用：瀏覽器在這種模式不准讀 JSON 檔，所以會改用 `index.html` 裡內嵌的章節表備份。

## 改章節表

1. 改 `data/math-kx-108.json`（每節的 `id` 一旦有學生用過就不要改，改名稱沒關係）。
2. 跑 `python3 embed_catalog.py`，讓內嵌備份跟著更新。
3. 開 `?selftest=1`，確認「內嵌備份章節表＝data JSON」通過。

## 改版規則（重要）

每次改了任何檔案要上線，就把 `sw.js` 第一行附近的 `CACHE = "huikao-v4"` 數字 +1（例如 v4 → v5）。這是「網路優先」快取：有網路就抓新版，沒網路才用舊版；改數字是為了把手機裡的舊備份清掉。

## 設定

- 會考日期：`index.html` 裡的 `EXAM_DATE = '2027-05-15'`（暫定，公告後改這裡）。

## 開啟雲端同步（P3，一次性設定）

比喻：Supabase 像一個「有門鎖的雲端檔案櫃」。下面三步是「做好抽屜、裝好門鎖、試鎖」，第四步是「發鑰匙給學生」。

1. **建抽屜與門鎖**：登入 Supabase → 選統測單字 App 用的那個專案 → 左邊「SQL Editor」→ 新增一個查詢 → 把 `supabase/001_hk.sql` 整份貼上 → 按 Run。
   - 成功時最下面會出現一張小表「有老師權限的帳號（會考複習）」，**確認裡面只有你自己的 email**。有別人就照檔尾那行指令刪掉。
   - 這一步只會新增 `hk_` 開頭的東西，不會動到統測單字 App 的資料。
2. **試鎖**：同一個地方再新增一個查詢 → 貼上 `supabase/002_verify_hk.sql` → Run。
   - 畫面出現**紅字**，而且開頭是「驗證全部通過」＝成功（紅字是故意的，用來把測試資料自動清掉）。
   - 開頭是「FAIL」或其他錯誤 → 先不要給學生用，把整段訊息截圖給 Claude。
3. **上線**：把整個資料夾部署到網站（GitHub Pages）。這次 `sw.js` 已經是 `huikao-v4`，不用再改。
4. **發鑰匙（建立第一位學生）**：
   - 打開 `你的網址/?teacher=1` → 用統測單字 App 的老師帳號密碼登入。
   - 在「新增學生」填**暱稱**（不要用全名）→ 按「新增並產生專屬連結」→ 按「複製連結」。
   - **這個連結只會出現這一次**，請私訊給學生本人或家長，不要貼到群組。
   - 學生用手機打開連結 → 畫面上方出現「暱稱・已同步」就代表接上了。要在電腦上也用，同一個連結在電腦再開一次即可。
   - 如果學生之前已經在這台裝置用過（單機版），第一次接上時會問要不要「合併」：學生自己的裝置請按「確定」。

### 加上每日備份（003、004，一次性）

比喻：在檔案櫃旁邊加一台「每天早上自動影印」的影印機。學生每天第一次存檔前，雲端會先把他原本的進度影印一份收起來；連結外流被亂改時，可以拿某一天的影本放回去。學生端完全碰不到影本。

1. **貼上 003**：SQL Editor → 新增查詢 → 貼上 `supabase/003_hk_backup.sql` 整份 → Run。看到 Success 就好。
2. **再貼 004**：再新增一個查詢 → 貼上 `supabase/004_verify_backup.sql` → Run。
   - 紅字開頭是「備份驗證全部通過」＝成功（紅字是故意的，測試資料會自動清掉）。
   - 開頭是「FAIL」或其他錯誤 → 截圖給 Claude。
3. **再跑一次 002**：貼上 `supabase/002_verify_hk.sql` → Run，一樣要看到「驗證全部通過」。（003 換掉了存檔的函式，這步確認原本的規則沒被改壞。）
4. 網頁不用重新部署，`sw.js` 也不用改：這次只動雲端。

備份全部保留、不會自動刪（量很小）。要退回某天的進度，照 `supabase/SECURITY.md` 最後「救援」那段做（記得先重設連結）。

### 日常
- 連結外流或弄丟：老師端該學生旁邊按「重設連結」→ 舊連結立刻失效，進度不會不見 → 把新連結再私訊一次。
- 學生畫面上方顯示「連結已失效」：代表老師重設過連結，請學生點那行字，貼上新連結。
- 老師端只能看、不能改學生的分數或計畫；在共用電腦用完請按「登出」。
- 安全設計與限制（例如：兩台離線各按一次完成只算一次）詳見 `supabase/SECURITY.md`。
